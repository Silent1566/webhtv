## A. 需要外部环境

### A1 · SMB 起播与拖动进度（FORK-4）

- **需要**：一台开 SMB 的机器（NAS / Samba / Windows 共享均可），共享名 + 账号密码，手机或模拟器与它同网段。
- **步骤**：设置 → 增强功能 → SMB 局域网浏览 → 填 `主机` 或 `主机:端口` + 共享名 + 账号 → 连接 → 进子目录 → 点视频 → 拖动进度。
- **通过判据**：视频起播且画面推进；拖动进度后 `TV-playback-progress` 的 `positionMs` 跳到目标区间；`logcat -b crash` 无 FATAL。
- **失败判据**：`SmbDataSource.read` 抛 `SMBRuntimeException`；或 `TV-player: ... cause=...` 指向解码/容器不支持（属另一类问题，按新任务处理）。
- **已知干扰**：impacket 用户态服务在第一次 READ 就 `Unable to deserialize SMB2 Packet Data`，那是**测试服务**的报文问题，不要当成产品缺陷。
- **记录位置**：`docs/FORK-4-smb-browser-decision.md` 的"实施记录与实机验证"。

### A2 · 遥控端到端（FORK-5）

- **需要**：可用的中转服务（App 内"远程托管"能绑定成功）+ 两台在线设备（一台手机当遥控、一台 TV 或另一台手机当被控）。
- **步骤**：两台绑定同一组 → 手机长按"远程托管"打开面板 → 依次发 `播放/暂停`、`下一集`、`快进 10 秒`、`返回`、方向键。
- **通过判据**：被控端 1 秒内响应（决策文档验收标准第一条）；同一命令不出现"双触发"（例如"下一集"跳两集）；返回后的焦点行为与实体遥控一致。
- **失败判据**：回包 `Unsupported player action` 或 `No active screen to receive the command`；或 1 秒内被控端毫无反应。
- **记录位置**：`docs/FORK-5-remote-control-decision.md` 的"仍未验"一节。

## B. 本机可补，但需要一个稳定片源

前置：多集竖屏短剧，连续播放 2 分钟不缓冲（真实 NAS 上的短剧目录最省事，可与 A1 合并成一次会话）。

### B1 · 亮度/音量是否真的生效

- **测点必须避开系统边缘手势区**：亮度用 x≈150、音量用 x≈900。x=80 / x=1000 会被系统"边缘返回"手势吃掉，测不到 App 的处理。
- **通过判据**：滑动后立刻截图能看到亮度/音量浮层，且数值或画面亮度确实变化；`TV-vpage` 不应出现 `settle ... commit=true`。
- **现状**：只验到"不换集"，没验到"真的改了数值"。

### B2 · 对端页"↓ 集名"可见帧

- **手法**：后台执行 `adb shell input swipe 540 1500 540 650 3500`，约 1.4 秒后截图。
- **通过判据**：截图里能看到对端页与"↓ 第 N 集"提示。
- **现状**：手法已对，三次采样都赶上缓冲黑屏。
